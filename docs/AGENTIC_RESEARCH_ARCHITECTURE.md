# Phase 3.6 agentic research architecture

SIRFEX core simulation, search, replay, and evaluation remain independent of the optional `agents` extra. The numerical policy diagnostics also run without Groq or LangGraph. The optional research layer consumes verified local evidence, proposes one typed intervention, independently validates it, waits for an explicit training approval flag, and delegates PPO continuation to the existing Stable-Baselines3 path. The model never supplies physical measurements or eligibility decisions.

`sirfex.research.workflow` uses a bounded LangGraph proposal flow: numerical evidence analyst → proposal selector → Pydantic and semantic validator → frozen plan. Invalid structured proposals can be retried within the two-call maximum; duplicate configurations stop. The graph checkpoint is in memory for the current process. JSON files in `artifacts/research/<run-id>/` are the durable evidence record. The execution graph has an approval gate, bounded training, development evaluation, deterministic guardrails, and a critic. A completed run records its source and candidate checkpoint hashes, actual interactions, exposure, development metrics, decision, and interpretation.

The selector can be Groq `openai/gpt-oss-120b`, an offline mock for CI, or a deterministic non-LLM selector. All use the same proposal registry. The Groq client sends compact development summaries only and has no shell, filesystem, Git, or final-holdout tools. There is no model call at every simulation step. The proposal and execution graphs are bounded and terminate; interrupted runs retain local evidence, but automatic mid-PPO resume is not implemented.

The primary model and JSON-schema response format were checked against [Groq's model documentation](https://console.groq.com/docs/model/openai/gpt-oss-120b) and [structured-output documentation](https://console.groq.com/docs/structured-outputs). Groq rejected Pydantic's tagged-union schema in strict mode with HTTP 400, so the adapter uses best-effort JSON-schema mode and applies strict Pydantic plus independent semantic validation locally. Actual account-specific rate limits must be read from the account; [Groq's rate-limit documentation](https://console.groq.com/docs/rate-limits) describes the mechanism. A live 120B proposal and approved local PPO continuation have now been exercised; the model did not perform PPO optimization itself.

# Robustness evidence and reproducibility (Checkpoint 1)

Calibration artifacts live under `artifacts/robustness/<run-id>/`, independent of historical study stores. The protocol, per-controller/per-anchor cases, status counts, JSON report, rendered Markdown and timing calibration have versioned schemas. Canonical JSON SHA-256 hashes identify protocol and cases; PPO identity uses the checkpoint's recorded SHA-256 rather than its machine-local path. The existing PPO loader verifies checkpoint bytes before inference. The report's semantic hash covers its content, and `sirfex robustness report --input <report.json> --output <report.md>` verifies that hash before deterministic regeneration.

Case files and status snapshots are written through temporary files and atomic replacement. A rerun with the same protocol reuses verified completed cases, retries failed cases and rejects incompatible protocol IDs, duplicate work items or corrupt case hashes. A forced-interruption test compares resumed and uninterrupted semantic result hashes. Per-case failures remain visible as `invalid` or `failed`; missing work is `pending`; completed censoring is counted separately. Differential results carry protocol and result hashes. Deterministic Class B repeats use the repository's episode comparison logic. Python, SIRFEX and checkpoint metadata, Git HEAD, config hash, seeds and replay status are recorded where available.

The calibration CLI accepts only `software_calibration_only` and imposes strict size limits. `--mode calibration` must be explicit. The output is not a frozen scientific protocol. CPU timing includes cold imports and setup; measured run throughput and controller-only timing must be interpreted separately. A simple 82,000-episode multiplication is a planning illustration, not a validated wall-time forecast for different horizons, hardware or controller mixtures.

Checkpoint 1 was pushed as commit `8e1c6298ab3899436580a925fa2cc7b1c4b0880b`. Its original tests and calibration ran locally. Checkpoint 1.1 adds storage-enforced write-once completed cases, explicit failed-case recovery, exclusive local writer locks, and selected differential trajectories in the existing `ExperimentStore`. Each headline now distinguishes in-memory repeat status, persisted repeat comparison, and independent regeneration status. Completed cases reject conflicting writes; a stale `.run.lock` or per-case `.lock` after a process crash requires an operator to verify that no writer remains before manually removing it. These local locks reject concurrent writers but do not provide a distributed multi-host lock or protection from deliberate filesystem tampering.

Prepared disturbance grids now bind anchor, direction, deltas, exact transformed scenarios, environment and analyzer versions, protocol SHA-256, feasibility classifications and viability. Revalidation uses an exact scenario-keyed analyzer cache so the same physical analysis is not repeated across controllers. A semantic hash detects accidental alteration, while recomputing expected preparation prevents a caller from legitimizing fabricated metadata by rehashing it.

The Phase 3.4/3.5 sealed final partitions are outside this workflow. Use only synthetic or explicitly permitted development inputs. Inspect `docs/PHASE_3_7_CHECKPOINT_1_1_REPORT.md` for the hardening tests, revised CPU calibration, and remaining scientific protocol decisions.

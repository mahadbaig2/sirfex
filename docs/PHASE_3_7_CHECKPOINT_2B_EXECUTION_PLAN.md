Have the human reviewer explicitly approve the exact proposed frozen bytes, semantic and raw hashes, 15 PPO identities, two references, 55-scenario development manifest, ordered grid, directed pairs, endpoints, resource caps, and conservative crash accounting. Record the decision in a review trail. A CI pass is not authorization.
2. After that decision, create the approved frozen JSON as described in the [freeze review](PHASE_3_7_CHECKPOINT_2B_FREEZE_REVIEW.md). Commit it without changing any scientific design field. Check its raw bytes against `git show <full-frozen-commit>:<protocol-path>`. If any byte or semantic hash differs from the decision, stop for renewed review.
3. Run the read-only dry-run with the frozen file and development manifest. Verify checkpoint hashes, manifest and search-space identities, 17 controllers, 12 anchors, seven pairs, exact plan hash and work counts. The self-hash detects accidental changes; the reviewer must independently verify the human decision. The record is not supplied or generated by Stage 1.
5. Only after those checks, the operator supplies the approved protocol semantic digest and record to the guarded CLI. No operator should treat placeholders below as approvals.

## Stop, recovery and evidence

The runner verifies committed protocol bytes, authorization record, input hashes and plan before controller work. Each work item has an atomic status and immutable completed evidence. The ignored local run directory is `$RunRoot/study_<approved-work-plan-sha256-first-20-hex>/`; it contains `plan.json`, prepared-grid and proposal records, work journal, budget ledger, authorization snapshot, invocation requests, compact cases, selected durable experiments, and complete or partial JSON/Markdown reports. Preserve it for audit and backup; do not commit ignored model binaries or run artifacts to Git. The full trajectories are retained for selected headline findings, while routine grid cells remain compact. Record the run-root path, disk free space, command invocation and output hashes in the operator log.

The caps are cumulative: eight hours wall time, 1,800 evaluation seconds per PPO, 2 GiB artifact bytes. A cap exhaustion or interruption preserves completed work and yields `partial_incomplete` evidence; it is not a complete scientific result. Inspect `invocation.json`, the budget ledger, stage counts and partial report. On an unclean restart, downtime can be charged conservatively to wall time and active controllers. Do not reset budgets, delete cases, change input identity, or silently extend limits. An extension needs a new review and approval.

After an authorized interruption, use the same identities and run root:

```powershell
sirfex robustness study --mode resume --protocol $Protocol --manifest $Manifest --approval-digest $ApprovedDigest --authorization-record $ApprovalRecord --frozen-commit $FrozenCommit --output-dir $RunRoot
sirfex robustness study --mode report --protocol $Protocol --manifest $Manifest --output-dir $RunRoot
```

The report command regenerates from verified evidence. A complete scientific report requires all mandatory work and planned paired coverage. Missing cases are not imputed; invalid, infeasible, unknown and censored outcomes remain separate. Never interpret a partial report as a full controller comparison.

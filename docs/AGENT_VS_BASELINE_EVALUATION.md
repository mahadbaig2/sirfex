# Agent versus non-LLM evaluation

The only completed matched pair is a **software smoke**: offline mock selector `20261027T192619_707a8c02ae` versus deterministic non-LLM selector `20261027T192827_51f292034e`. Both used seed 3's same source checkpoint, evidence context and development partitions, 256 continuation interactions, and the same continuation seed. Each observed 15 stress interactions and one completed stress episode. Both measured nominal MAE 0.054527 and development stress MAE 0.270660, with stress violation frequency 0.25. Both were classified `smoke_inconclusive`. These identical short-run results do not imply the interventions are equivalent at adequate exposure.

The mock made one fixture proposal call and zero LLM calls. The deterministic selector made one selection call and zero LLM calls. A real GPT-OSS proposal is now available, but there is still no GPT-OSS **training** result or token-cost comparison of completed strategies, and no claim that an LLM selects better interventions. An earlier Groq proposal attempt without `GROQ_API_KEY` was recorded as `provider_failed`, with no model response or PPO execution.

The bounded design for an actual development pilot is in [the experiment protocol](AGENT_EXPERIMENT_PROTOCOL.md). Its agent and non-LLM arms must be compared only after equal-budget proposals are approved and executed. Final holdouts remain sealed. Machine-readable local smoke records can be verified with `sirfex research verify`; the compact public export is [Phase 3.6 smoke evidence](evidence/phase_3_6_smoke.json).
